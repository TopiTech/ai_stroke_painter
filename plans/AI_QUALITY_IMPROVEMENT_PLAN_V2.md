## 1. 背景と現状の課題分析（提示画像に基づく実態分析）

ユーザーから提示された生成イラスト（画像1: アニメ美少女キャラクター、画像2: 夜景/山岳モチーフ）の分析、およびリポジトリコード（`libs/ui/aiillustration`）の調査に基づき、現在の描画クオリティを著しく低下させている根本原因を特定しました。

```

│      Goal Mode でステップごとに重複蓄積して猛吹雪ノイズと化している │
```

## 2. クオリティ格段向上のための 5大改革方針

| 改革の柱 | 概要 | 狙い・効果 |
| :--- | :--- | :--- |
| **方針1: 点々作画（パーティクル・点描ノイズ）の根絶・抑制 ★追加** | プロンプトでの無差別推奨を撤廃し、顔面除外マスク・蓄積上限・微小ゴミ点除去・UIトグルを導入 | 画面全体を覆う鬱陶しい白い斑点・大雪ノイズが完全消失し、クリアな画質に |
| **方針2: 高次セマンティック・プリミティブの導入** | 生の点列ポリゴンではなく `anime_eye`, `hair_strand_bundle`, `anime_face` 等の高水準パーツを定義し、レンダラー側で幾何学的に完璧なアニメ描画を行う | 瞳の輝き・まつ毛・前髪の束感が一瞬でプロクオリティに跳ね上がる |
| **方針3: スマート顔面マスク & パーツ整合** | 肌領域・顔面バウンディングボックスを検出し、主役の表情にノイズが干渉しないよう保護 | 顔のパーツが美しく際立ち、チークや陰影が自然に溶け込む |
| **方針4: Goal Mode の単一アートボード型ライフサイクル** | レイヤーグループ乱立を廃止し、1つの標準スタック（Flats〜FX）を「生きたキャンバス」として差分更新・上書き洗練 | ステップを重ねるほど絵が美しく洗練され、重なりによる濁りを防止 |
| **方針5: Few-Shot 規範幾何辞書 & プロンプト刷新** | 抽象的ルールではなく、美しいアニメ顔・瞳・髪の「黄金比規範幾何」を Few-shot で提示 | LLMが迷わずプロ水準の形状比率・座標を出力できるよう誘導 |

## 3. 具体的な改善施策（フェーズ別詳細計画）

### Phase 1: 即効・最優先施策（点々作画の抑制 & 顔・髪パーツの劇的改善）

#### 1.1 「点々作画（パーティクル・点描ノイズ）」の徹底抑制 ★重点追加
どちらの絵にも画面全体に現れている白い十字星やドットの散乱を、以下の多層防御で徹底的に抑制します。
1. **プロンプトでの無差別 FX 推奨の是正**:
   - `KisAiPromptAnalyzer::generateGoalPhaseGuidance()` において、Phase 4 の「Dynamic FX: Floating petals, embers, stars, or light sparkles」の強制指定を改め、**「ユーザーから明示的な指示（星空、雪、吹雪、キラキラ、魔法等）がない限り、画面全体への particles の配置を厳禁とする」** という厳格なネガティブ制約を追加。
   - `budget_allocation` における `Highlights_FX` の比率を `Highlights`（面の光沢・ツヤ・照り返し）中心に再定義。
2. **Goal Mode でのパーティクル多重蓄積の遮断**:
   - 既にキャンバスまたは前ステップに `particles` が存在する場合、後続ステップでの追加出力を自動ドロップ（多重生成の根絶）。
3. **Face / Subject Exclusion Mask（主役・顔面除外マスク）**:
   - `Flats` レイヤーの肌色ポリゴン（`id` に `skin`, `face` を含むもの）から顔面領域のマスクを生成し、パーティクルが顔面・目・鼻・口・髪の主要部に落ちることをステンシルマスクで遮断。パーティクルは背景のごく周辺にのみ制限。
4. **孤立微小点（1点パス・ゴミ点描）のランタイム除去**:
   - `refineForRendering()` において、意図しない 1 点パス（点描）や極小の 2 点パス（長さ < 0.005）を自動検出し、ノイズとしてドロップ。
5. **UI に「FX パーティクル抑制」トグルを追加**:
   - Docker の詳細設定に「点々/パーティクルを抑制する（既定: 有効）」チェックボックスを設置し、ユーザーがワンクリックで完全オフにできるようにする。
- **対象**: `KisAiStrokeRenderer.cpp`, `KisAiPromptAnalyzer.cpp`, `KisAiStrokeProgram.cpp`, `KisAiIllustrationDocker.cpp`

#### 1.2 高次アニメ瞳プリミティブ (`anime_eye`) の導入 & プロシージャル瞳生成
- **現状**: LLM が瞳を表現しようとして青い丸（fill）やウォッシュを適当に置くため、白目・アイライン・瞳孔・ハイライトが崩壊。
- **施策**:
  1. `KisAiStrokeOperation::Kind` に `AnimeEye`（または `path`/`fill` を束ねる複合オペレーション）を追加、または LLM が出力しやすいスキーマを定義:
     ```json
     {
       "kind": "anime_eye",
       "id": "left_eye",
       "center": [0.38, 0.42],
       "size": [0.12, 0.14],
       "iris_color": "#3b82f6",
       "secondary_color": "#93c5fd",
       "style": "sparkle",
       "expression": "open",
       "direction": "front"
     }
     ```
  2. レンダラー側でプロシージャルに以下を完全自動合成:
     - 柔らかな影の入った白目（Sclera）
     - 豊かな縦グラデーション＋下部反射光を持つ虹彩（Iris）
     - 深いインディゴの瞳孔（Pupil）
     - 美しいアイラインと先細りまつ毛（Upper/Lower Eyelash curves）
     - 瞳のハイライト（Catchlights: 星型または2点デュアルグローブ）
  3. 既存の `Kind::Path` / `Kind::Fill` 形式で出力された場合でも、`id` が `eye` や `iris` を含むものを検知してプロシージャルに瞳の補正・ハイライト追加を行う後処理（Smart Eye Enhancer）を実装。
- **対象**: `KisAiStrokeProgram.h`, `KisAiStrokeRenderer.cpp`, `KisAiStrokeQualityUtils.cpp`

#### 1.3 髪の毛の「モコモコ円パッチ」自動統合 & 束感リボン化
- **現状**: LLM が髪の毛を数十個の小さな円/多角形の `fill` として出力し、泡やアフロのようになる。
- **施策**:
  1. `expandProceduralOperations` を拡張し、`Flats` レイヤーにある `hair` 関連の重複ポリゴン群を解析。
  2. 近接・重複する微小ポリゴン群をブーリアン結合（`QPainterPath::united`）して1つの大きな美しい髪のベースシルエット（Continuous Hair Silhouette）へ統合。
  3. 頭頂部から毛先に向かう主要ストロークから、滑らかに先細る毛束（Ribbon Clumps with Tapering）を自動生成。
  4. 空間に浮遊する針金のようなハイライト（Halo）の誤配置を安全弁でクランプ。
- **対象**: `KisAiStrokeRenderer.cpp`, `KisAiStrokeQualityUtils.cpp`

#### 1.4 チーク（Blush）と鼻・口のプロポーション自動適正化
- **現状**: 頬に不自然なピンクの丸が浮き、鼻の位置に黒い縦長の染みが置かれている。
- **施策**:
  1. `id` に `blush` や `cheek` を含む操作は、円のベタ塗りではなく、ソフトガウシアン（径方向グラデーション、中心アルファ 35%、周囲アルファ 0%）の自然な血色メイクとしてレンダリング。
  2. 鼻（`nose`）の Shading は、黒い多角形ベタ塗りを禁止し、微小なドット（ハイライト）と肌色よりわずかに暗い暖色シャドウのみを許容するランタイム補正。
- **対象**: `KisAiStrokeRenderer.cpp`, `KisAiStrokeQualityUtils.cpp`

### Phase 2: Goal Mode とレイヤーライフサイクルの刷新

#### 2.1 単一アートボード型レイヤースタック（Single Living Canvas）
- **現状**: Step ごとに別々のレイヤーグループ（`🎨 AI [Step 1/6]`, `🎨 AI [Step 2/6]`...）が追加され、キャンバス上がレイヤーの山になり、ストロークが累積して絵が濁る。
- **施策**:
  1. Goal Mode において、単一の親グループ（`🎨 AI Illustration`）を保持。
  2. 内部レイヤー（`Background`, `Flats`, `Shading`, `Lineart`, `Highlights`, `FX`）を各ステップで破棄・全置換または選択的クリーンアップ。
  3. フェーズ進行（Step 1: 下地確定 → Step 2: 陰影付与 → Step 3: 線画洗練 → Step 4: 仕上げ）に応じて、前のステップのベースを活かしつつ、不整合なノイズをクリーンアップ。
- **対象**: `KisAiStrokeRenderer.cpp`, `KisAiIllustrationDocker.cpp`

#### 2.2 視覚批評（Agent Critique）のフィードバック精緻化
- **現状**: Vision API は全体の印象をテキストで返すのみで、具体的な座標やどのパーツが崩れているか（「髪が泡状になっている」「点々が多すぎる」）を指摘できていない。
- **施策**:
  1. Goal Mode の Vision 批評プロンプトに「Anime Aesthetics Quality Checklist」を導入:
     - 瞳のアライメントとハイライトの有無
     - 顔面・画面全体の不要な点々ノイズの有無
     - 髪の毛の束感とシルエットの滑らかさ
  2. 検出された問題点に応じて、次ステップの生成指示（directive）へピンポイントで修正タスクを注入。
- **対象**: `KisAiStrokeProgram.cpp`

### Phase 3: プロンプト & Few-Shot 規範幾何テンプレートの導入

#### 3.1 アニメ顔・目・髪の規範幾何 Few-shot 辞書
- **現状**: プロンプトに抽象的なルールが書かれているが、LLM は「具体的にどんな座標配列を書けば美しいアニメ絵になるのか」を知らない。
- **施策**:
  1. キャラクター指定時（`DomainType::Character`）に、プロンプト内に「規範幾何テンプレート（Canonical Geometric Archetype）」を注入:
     - 黄金比に基づいた頭部・顎ラインの座標例
     - 左右対称に配置された目元・まつ毛・瞳の座標例
     - 前髪のM字バンク・サイドヘアの毛束（Ribbon）の座標例
  2. LLM はこの規範幾何をアンカー（基準）として、プロンプトに応じた表情・髪型・髪色・目の色にパラメータを調整して出力するため、幾何破綻が劇的に激減する。
- **対象**: `KisAiPromptAnalyzer.cpp`, `KisAiStrokeProgram.cpp`

---

### Phase 4: Krita ネイティブ機能との融合 & ハイブリッド展開

#### 4.1 Krita プリセットブラシ（KisPaintOpPreset）による実ブラシストローク化
- **現状**: 全て QPainter の単純なポリゴン・パスで描画されているため、Krita 本来の豊かな筆圧・テクスチャ・混色が生かされていない。
- **施策**:
  1. Krita の内蔵ブラシプリセット（`Pencil-2`, `Basic-5 Size`, `Chalk Soft`, `Airbrush Soft` 等）を `brush.profile` にマッピング。
  2. `KisPainter` を用いて、Krita の本格的なブラシストロークとしてキャンバスに打鍵・描画するネイティブラスタライズパスを提供。
- **対象**: `KisAiStrokeRenderer.cpp`

#### 4.2 （中長期オプション）AI下絵ストロークトレース・パイプライン
- **構想**: 高度な画像生成モデル（Stable Diffusion / Flux等）またはローカルモデルでラフ構図を生成し、それを輪郭抽出・ベクターポリゴン化して Krita のレイヤー別ストロークに落とし込むハイブリッド生成機能の設計。

## 5. 検証計画

### 自動単体テスト (`build-test`)
- `testParticleSuppressionRule`: プロンプトに星や雪の指示がない場合、particles が出力されない（またはドロップされる）ことの検証。
- `testFaceExclusionMask`: 顔面バウンディングボックス内にパーティクル座標が侵入しないことの幾何学的テスト。
- `testIsolatedPointNoiseDrop`: 長さ極小の孤立点ゴミストロークが refine でドロップされることの検証。
- `testAnimeEyeProcedural`: `anime_eye` プリミティブまたは補正ロジックが、有効な瞳構造（白目、虹彩、まつ毛、ハイライト）を生成することの検証。
- `testHairMeshUnion`: 重複する髪の毛ポリゴンが1つの滑らかなシルエットにブーリアン結合されることの検証。
- `testGoalModeSingleArtboard`: Goal Mode 実行時にレイヤーグループが重複生成されず、単一スタック内で更新されることの検証。

### 実機検証 (`run-ai-stroke-painter.bat`)
- 提示された画像と同一プロンプト（アニメ美少女、夜景）を実行し、画面を埋め尽くしていた点々ノイズが根絶され、各パーツの品質が向上していることを確認。
